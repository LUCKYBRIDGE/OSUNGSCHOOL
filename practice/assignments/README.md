과제 1과 선택 과제를 한 게시글로 제출해도 됩니다. 제출 시기와 수업 중 작업 시간은 강사의 안내를 따릅니다.

## 공통 조건

1. **`overview.md` 또는 `prd.md` 하나**: 대상, 해결할 문제, 목표, 사용 조건, 이번 범위, 완료 기준을 적습니다.
2. **`design.md`**: 결과물의 구조·흐름·문구·색·글자·선택지·오류 복구 기준과 이유를 적습니다. 아이디어 과제는 계획한 기준, 포스터는 지면 기준으로 작성합니다.
3. 학생의 수행 조건과 교육적 이유를 설명하고, 실제 학생 이름·사진·진단명·개별 기록은 넣지 않습니다.
4. 실제로 확인한 내용과 아직 확인하지 못한 내용을 구분합니다. 생성된 파일이나 링크가 열리는지 직접 확인합니다.
5. **가능하면 Figma MCP를 활용합니다.** 연결 가능한 경우 설계 읽기 → 결과물 반영 → 비교·수정에 활용합니다. 연결되지 않으면 설계 문서와 직접 확인으로 진행하고 미사용 사유를 적습니다. 필수 조건은 1·2번 문서와 선택 과제의 결과물입니다.

이 연수의 기존 `PROJECT_OVERVIEW.md`·`DESIGN.md`와 역할은 같습니다. 이번 제출용 예시는 소문자 파일명을 사용합니다. 이미 작성한 개요는 내용을 옮겨 `overview.md` 또는 `prd.md`로 정리하고, 같은 개요를 두 파일에서 중복 관리하지 않습니다.

## 예시를 사용하는 순서

1. 과제 1 폴더의 개요·설계·아이디어 양식을 읽고 자신의 문제로 고칩니다.
2. `prompt.md`의 첫 요청문을 복사합니다. 파일 첨부가 가능한 AI에는 두 문서를 함께 줍니다. 첨부가 안 되면 파일 이름을 적고 내용을 대화에 붙여 넣습니다.
3. 질문에 답하고 문서부터 확정합니다. 과제 2·3·4 중 하나의 폴더로 진행합니다.
4. 한 화면 또는 한 장부터 만들고 직접 확인한 뒤 고칩니다. 문서도 실제 결과와 맞춥니다.
5. [제출 양식](submission.md)을 채우고 **‘08 · 결과물 제출’에 새 게시글**을 올립니다. 안내 글의 댓글에만 제출하지 않습니다.

예시 파일은 완성품이나 정답이 아닙니다. 선택지 수·글자·그림·지원 방식은 학생의 수행 조건에 맞게 바꿉니다. AI가 임의로 기능을 줄이거나 늘리기보다 교사가 정한 목표를 따르게 합니다.

## 제출 방법: 파일 또는 링크

다음 중 한 방식으로 제출합니다. 결과 링크만으로 공통 문서가 보이지 않으면 두 문서도 함께 첨부합니다.

- **ZIP**: 아이디어 글, 공통 문서, 선택 과제 결과, 실행·확인 기록을 한 폴더에 담습니다. 웹은 실제로 필요한 HTML·그림·스타일·스크립트 파일을 포함합니다. `node_modules`, 비밀 키, 로그인 정보는 담지 않습니다.
- **사이트 링크**: 결과 주소와 개요·설계 문서 링크 또는 첨부를 제공합니다. 첫 화면부터 완료·복구까지 확인할 수 있어야 합니다.
- **GitHub 저장소 링크**: 공통 문서·결과 파일·실행 방법을 저장소에 둡니다. 제출 링크가 가리키는 버전이나 커밋도 적으면 수정 이력을 확인하기 쉽습니다.
- **Figma 링크**: 확인할 페이지·프레임을 지정합니다. 결과물과 개요·설계 문서를 함께 제공합니다. 과제 2의 Figma 시안만으로 작동하는 웹 제출을 대신할 수는 없습니다.

게시글 제목 예: `[과제2] 카페 주문 연습 · (제출용 이름)`.
제출은 `submission.md`의 본문을 복사해 채웁니다. 링크는 확인자에게 열리는 권한인지 시험합니다. 공개 링크에 학생 정보가 들어 있으면 안 됩니다. 공개가 어려우면 강사가 지정한 학교 내부 방식으로 공유합니다.

## 확인과 피드백

점수보다 다음 항목을 보고 ‘확인 완료 / 보완 필요 / 실행 미확인’과 이유를 남깁니다. Figma MCP 미사용 자체는 보완 사유가 아닙니다.

- 대상·문제·목표가 서로 연결되는가?
- 공통 문서와 결과물이 같은 범위·설계 기준을 따르는가?
- 학생의 선택·이해·실수 복구 또는 자료 읽기 조건을 고려했는가?
- 웹은 작동하고, 지면 자료는 한글·순서·출력·근거가 확인되는가?
- 다른 교사가 파일 또는 링크를 열어 다시 사용할 수 있는가?

피드백 예: “메뉴 선택과 주문 확인은 직접 확인했습니다. 선택 표시가 색만으로 되어 있어 테두리와 ‘선택됨’ 문구를 추가하면 좋겠습니다. 태블릿 실행은 아직 미확인입니다.”

## Figma MCP 선택 심화

설계에서 가져온 요소와 실제 결과를 비교하는 데 사용합니다. 아래 문장을 해당 MCP가 연결된 AI에 보내세요.

```text
overview.md와 design.md를 먼저 읽어줘.
Figma의 (파일·프레임 링크)를 MCP로 읽고, 실제로 읽은 프레임을 알려줘.
가능한 경우 설계 구조·글자·색·간격과 화면 캡처를 함께 확인해줘.
그 기준을 이번 결과물에 반영하고, 결과와 설계를 비교해 차이 3개를 고쳐줘.
우리 학생의 수행 조건과 맞지 않는 설계는 이유를 설명하고 문서도 수정해줘.
연결되지 않거나 지원하지 않는 기능이면 성공했다고 하지 말고,
내가 제공할 캡처·설계 문서로 진행하는 방법을 알려줘.
```

기록할 것: 읽은 Figma 프레임, 반영한 요소 하나, 비교해서 고친 점 하나. 웹 과제는 별도로 버튼 동작을 확인합니다. Figma 디자인 링크를 붙인 것과 MCP를 실제 호출한 것은 구분합니다.
