# design.md · 아이디어 단계의 설계 기준 예시

## 결과물 방향
- 계획한 결과물은 카페 주문 연습 웹이다. 아직 구현 완료한 것으로 쓰지 않는다.
- 포스터·활동지·다른 결과물을 선택한다면 아래 화면 기준을 해당 지면·매체 기준으로 바꾼다.

## 흐름과 문구
- 한 단계에는 중심 행동 하나를 둔다: 고르기 → 수량 → 확인 → 완료.
- ‘메뉴 선택’보다 ‘마실 것을 골라요’처럼 학생이 할 행동을 적는다.
- 항상 지금 단계와 바꾸기·도움 위치가 보이게 한다.

## 읽기와 선택
- 웹 예시: 제목 32px 이상, 본문 24px 이상, 버튼 높이 64px 이상.
- 그림에는 이름을 함께 적는다. 선택은 색뿐 아니라 테두리와 ‘선택됨’ 문구로 표시한다.
- 예시 색: 배경 #FFFFFF, 본문 #1F2933, 주 버튼 #1D5FD1. 실제 대비와 기기 표시를 확인한다.

## 실수와 반복
- ‘틀렸어요’만 보여 주기보다 ‘음료를 먼저 골라요’처럼 다음 행동을 안내한다.
- 바꾸기에서 이전 선택을 유지하고, 다시 시작하면 초기화한다.
- 제한 시간·깜빡임·자동 화면 전환은 기본으로 넣지 않는다.

## 선택 심화와 확인 계획
- 가능하면 Figma 프레임의 흐름·버튼·글자 크기를 MCP로 읽어 기준을 비교한다.
- 연결 불가이면 종이 스케치나 문서로 비교하고 그 방법을 기록한다.
- 제작 전에는 문구·선택지·돌아가기 위치를 검토한다. 실제 동작 확인은 제작 과제에서 한다.
