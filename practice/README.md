## 준비: 쓸 수 있는 작업환경을 고릅니다

두 환경 모두 아래 공통 요청을 씁니다. 익숙하고 사용 가능한 도구를 고르세요. 프로젝트 메뉴나 설치가 실습의 필수 조건은 아닙니다.

| 환경 | 시작 | 기준 전달 | 결과 확인 |
|---|---|---|---|
| 웹 채팅: ChatGPT·Gemini·Claude | 새 대화 또는 프로젝트·Gem | 메모·규칙·개요·최신 파일을 붙이거나 첨부 | 가능한 미리보기 또는 내려받은 파일을 직접 확인 |
| 전문 도구: Claude Code·Codex 등 | 프로젝트 작업 폴더를 열거나 그 폴더에서 시작 | 기존 파일과 규칙을 먼저 읽도록 요청 | 폴더의 결과 파일을 실행·검사하고 실제 기기에서도 확인 |

규칙은 같은 내용을 환경에 맞게 전달합니다. Codex는 `AGENTS.md`, Claude Code는 `CLAUDE.md`를 기준 파일로 쓸 수 있습니다. 두 도구에서 같은 규칙을 공유하려면 `CLAUDE.md`에 `@AGENTS.md` 한 줄을 넣어 기존 규칙을 참조할 수 있습니다. 규칙 본문을 두 파일에 반복해서 적을 필요는 없습니다. 기존 프로젝트에서는 이미 있는 규칙과 개요를 먼저 읽고 필요한 부분만 고칩니다.

처음 시작한다면 요청 1로 짧은 초안을 만든 뒤 읽고 고칩니다. 웹 채팅에서는 지침이나 대화에 전달하고, 전문 도구에서는 작업 폴더에 파일로 저장하도록 요청합니다. 준비나 실행이 안 되는 환경에서는 오류 메시지를 남기고 가능한 작은 작업부터 진행합니다.

## 요청 1. 처음: 문서부터

요청 1은 어떤 주제든 쓸 수 있다. 요청 2~3의 학생용 웹 화면 예시는 필요에 맞게 바꾼다. 요청 4는 작은 기능·화면·자료에 공통으로 쓴다. 자세한 운영 방법은 [활동 안내](activity_guide.md)를 참고한다. 질문에 모두 답한 뒤 시작할 필요는 없고, 개요와 규칙은 초안으로 정리해 만들면서 보완한다.

```text
나는 교사이고, 아래 아이디어를 실제로 만들어 보고 싶어.
(내 자유 메모)
진행에 꼭 필요한 정보가 빠졌다면 중요한 것부터 짧게 질문해 줘.
정하지 않은 내용은 제안하거나 미정으로 남겨 줘.
개요(PROJECT_OVERVIEW.md)와 작업 규칙 초안부터 짧게 정리해 줘.
```

## 요청 2. 화면 기준(DESIGN.md)

```text
PROJECT_OVERVIEW.md를 바탕으로 DESIGN.md 초안을 만들어 줘.
- 대상: (예: 고등부 학생, 학교 태블릿 가로 화면)
- 학생용 터치 화면 예: 한 화면에 행동 하나, 버튼 높이 64px 이상, 본문 24px 이상
- 선택 상태·안내를 색만으로 구분하지 않는다
만든 뒤에는 내가 고칠 만한 부분 3가지를 알려 줘.
```

## 요청 3. 그림 시안 (선택)

```text
DESIGN.md를 참고해 '(화면 이름)' 화면 시안을 그림으로 그려 줘.
태블릿 가로 화면, (예: 음료 그림 2개), 큰 버튼, 위쪽에 '(1/4 단계)' 표시.
```

그림 생성이 가능한 이미지 도구를 이용한다. 전문 도구로 구현할 때는 만든 시안을 작업 폴더에 두고 읽도록 요청한다. 생성 기능이 없거나 시안이 필요하지 않으면 생략해도 된다. 그림 속 한글보다 배치와 크기를 보고, 최종 문구는 직접 확인한다.

## 요청 4. 작은 부분부터 만들기

```text
개요와 기준을 참고해 '(작은 기능·화면·자료)'만 만들어 줘.
완료 기준: (예: 음료를 누르면 선택 표시가 바뀌고 '다음'이 켜진다)
확인한 방법과 결과, 아직 확인하지 못한 것을 알려 줘.
```

- 웹 채팅: 규칙·개요·설계 기준과 최신 결과물을 첨부한다. 웹 화면이라면 “내려받아 열 수 있는 HTML 파일로 만들어 줘”를 덧붙일 수 있다. 한 파일로 열 수 있는 작은 예시는 “모양과 동작을 포함한 HTML 파일 하나로” 요청해도 된다. 가능한 미리보기에서 눌러 보거나 결과 파일을 저장해 연다.
- 전문 도구: “현재 작업 폴더의 규칙·개요·DESIGN.md와 기존 파일을 읽고, 필요한 파일을 만들거나 수정해 줘. 실행·검사가 가능하면 수행하고, 실행 방법과 확인 결과를 알려 줘”를 덧붙인다. 웹 화면 외의 결과물은 주제에 맞는 파일 형식과 확인 방법을 정한다.

AI가 확인했다고 말하면 확인 방법과 결과를 함께 본다. 실행 도구나 권한이 부족했다면 ‘미확인’으로 남기고 교사가 직접 확인한다.

## 요청 5. 이어서 하기

```text
작업 규칙·HANDOFF.md·최신 결과물을 읽고, '다음 할 일' 중 첫 번째만 진행해 줘.
완료 기준: (예: 3단계에서 '처음부터'를 누르면 1단계로 돌아간다)
확인 결과와 미확인을 남기고, HANDOFF.md를 갱신해 줘.
```

## 막혔을 때

| 상황 | 이렇게 말한다 |
|---|---|
| 화면이 열리지 않는다 | "오류 메시지를 붙여 넣을게. 원인과 고치는 방법을 알려 줘" |
| AI가 너무 많이 바꿨다 | "방금 바꾼 것을 되돌리고, 요청한 부분만 다시 해 줘" |
| 대화가 길어져 헷갈린다 | "지금까지를 HANDOFF.md로 정리해 줘" → 웹 채팅에는 기준·최신 결과물과 함께 첨부, 전문 도구에는 같은 폴더에서 읽도록 요청 5 |
| 같은 실패가 세 번째다 | 멈추고 요청을 더 작게 나눈다 |

## 결과 파일을 남기고 확인하기

웹 채팅에서는 다운로드 가능한 결과 파일을 받아 저장한다. 단일 HTML 코드만 받았다면 코드 복사 → 메모장 → 다른 이름으로 저장 → `index.html` / 모든 파일 / UTF-8 순으로 저장하고 브라우저에서 연다.

전문 도구에서는 이미 작업 폴더에 만들어진 파일을 확인한다. “결과 파일 위치, 실행 방법, 확인한 것과 미확인을 알려 줘”라고 요청하고 안내에 따라 열어 본다. 문서·규칙·인계 기록도 같은 폴더에 남겨 다음 작업에서 읽게 한다.

웹 공개는 선택이다. 단순한 정적 웹 화면을 GitHub Pages로 공개할 때는 진입 파일 `index.html`을 게시 위치에 두고 Pages에서 브랜치와 폴더를 지정한다. 앞의 단일 파일 예시는 main · /(root)를 쓸 수 있다. 공개 주소에서 다시 확인한다. 문서·포스터 등 다른 자료는 맞는 저장·공유 방법을 쓴다.

## 학교에서 지킬 것

- 이름·사진·진단명 대신 '학생 A'와 수행 특성만 쓴다.
- AI는 교사가 쓰고, 학생은 완성된 화면만 쓴다.
- 무료 공개 주소(GitHub Pages)는 누구나 본다. 학생 기록은 두지 않는다.
- 그림은 직접 만들었거나 사용 허락이 분명한 것만 쓴다.
- 학교 계정 연결과 권한은 꼭 필요한 것만 허용한다.
- 안내 문구·가격·사실은 교사가 확인한다.
- 학교·교육청의 AI 활용 지침이 있으면 그것을 먼저 따른다.

## 양식: 규칙 (AGENTS.md)

학생용 터치 웹 화면을 만드는 예시다. 웹 채팅에서는 지침·대화에 전달하고, 전문 도구에서는 규칙 파일로 저장한다. 요청 1 없이 시작해도 되며, 다른 결과물은 대상·표현·확인 방법에 맞게 바꾼다.

```markdown
# 규칙 (AGENTS.md)
- 나는 특수학교 교사이고, 학생이 쓸 연습 자료를 만든다
- 학생 이름·사진·진단명 등 개인정보를 넣지 않는다
- 한 화면에는 행동을 하나만 둔다
- 버튼 높이 64px 이상, 본문 글자 24px 이상
- 요청하지 않은 기능을 더하지 않는다
- 진행에 꼭 필요한 정보만 먼저 묻고, 미정은 만들면서 보완한다
- 고친 뒤에는 무엇이 바뀌었고 어떻게 확인하면 되는지 알려 준다
```

## 양식: 인계 (HANDOFF.md)

막힐 때 참고하는 항목이다. 한 공간에 짧게 메모해도 되고, 해당하지 않는 항목은 비워 둬도 된다.

```markdown
# HANDOFF.md
## 지금 상태
- 
## 정한 것과 이유
- 
## 안 된 방법
- 
## 다음 할 일
1. 
```
