## 판단

‘우리 반’, ‘조건’, ‘연습 자료’가 각각 잘못된 말은 아니다. 다만 현재 교재에서는 **연수 전체의 범위, 특정 제작 사례, 참가자에게 시키는 활동이 같은 말로 표현**되어 있다. 그래서 교사 대상 문제해결 연수가 학급 운영 활동지나 학생용 생활 연습 화면 제작 수업처럼 좁게 읽힌다.

개선의 중심은 일괄적인 단어 치환이 아니라 **누가 읽는 문서인지, 누구에게 쓰일 결과물인지, 이번에 무엇을 만드는지**를 명확히 하는 것이다. 쉬운 말은 유지하되 제목과 질문은 구체적으로 쓴다. ‘요구사항 정의’, ‘사용자 페르소나 도출’ 같은 개발 용어로 바꾸는 것은 이 연수 대상에 맞지 않는다.

## 어색함이 생기는 이유

### 1. ‘우리 반’이 공통 범위를 대신한다

강사의 발화에서 “우리 반 학생은 어디에서 멈출까요?”라고 묻는 것은 구체적인 경험을 떠올리게 한다. 그러나 교재 전체 제목과 필수 입력란에 반복하면 모든 결과물이 학급 학생을 대상으로 해야 하는 것처럼 읽힌다. 교사의 기록 정리, 수업 타이머, 동료와 공유할 문서, 생활 장면의 안내도 이 연수의 가능한 문제다.

공통 안내에서는 ‘대상’, ‘사용 장면’, ‘해결할 문제’를 쓰고, 학생용 사례에서만 학생을 구체적으로 지칭하는 것이 적절하다. 특수교육 맥락을 없애는 것이 아니라, 학생의 수행 특성을 설계에 반영하는 설명에 집중시킨다.

### 2. 두 종류의 ‘연습’이 겹친다

참가 교사는 AI 활용을 실습하고, 제작한 카페 주문 화면에서는 학생이 주문 행동을 연습한다. 현재 ‘우리 반 연습 자료’는 이 두 활동을 구분하지 않는다.

- 교사가 하는 활동: 연수 실습, 제작 실습.
- 교사가 만드는 것: 웹 화면, 포스터, 안내문, 수업 도구처럼 결과의 종류를 명시한다.
- 학생이 하는 활동: 주문 연습, 하차 벨 누르기 연습 등 교육적 행동을 명시한다.

‘결과물’은 여러 형식을 묶어 안내할 때 쓰되, 개별 과제에서는 구체적인 이름으로 바꾼다.

### 3. ‘조건’이 서로 다른 질문을 묶는다

학생이 필요한 도움은 교육적 설계 정보이고, 태블릿·인터넷·설치 여부는 사용 환경이다. 버튼 크기와 색은 화면 기준이며, 이번에 만들 단계는 제작 범위다. 모두 ‘조건’으로만 반복하면 어느 칸에 무엇을 적는지 흐려진다.

활동지에서는 쉬운 질문으로 구분하고, AI에게 줄 문서에서는 ‘사용 환경’, ‘제작 범위’, ‘화면 기준’처럼 짧은 표준 이름으로 정리하는 것이 좋다. 기존 ‘사용 조건’ 개념을 강의 전체에서 삭제할 필요는 없다.

### 4. 친근한 발표 말투가 교재의 제목이 된다

‘우리 반’, ‘하나’, ‘작게, 끝까지’는 발화에서 도움이 된다. 교재 제목은 무엇을 만들고 어떤 작업을 할지 드러내야 한다. 성인 교사 대상 자료이므로 쉬우면서도 정확한 표현이 좋다. 친근함을 금지하거나 모든 문장을 딱딱한 명사형으로 바꿀 필요는 없다.

## 권장하는 개선 방향

### 공통 안내와 웹 제작 사례를 구분한다

연수의 공통 흐름은 **문제 파악 → 필요한 정보 정리 → 만들기 → 확인과 수정**으로 안내한다. 대상·사용 환경·제작 범위·설계 기준은 필요한 때 보완하며, 시작 전에 모든 항목을 확정하도록 요구하지 않는다.

현재의 기본 웹 실습은 그대로 하나의 구체적인 경로로 안내할 수 있다. “오늘 기본 실습에서는 학생용 생활 연습 화면을 만듭니다. 같은 작업 방법은 포스터와 교사 업무 도구에도 적용할 수 있습니다”처럼 연결한다. 카페 주문 사례를 다른 사례로 모두 바꾸거나, 모든 참가자에게 여러 종류의 결과물을 만들게 할 필요는 없다.

선택 과제를 기본 실습에 통합하려면 공통 계획 양식과 결과 유형별 제작·확인 안내를 나눈다. 제목만 바꾸고 모든 사람에게 웹의 단계·버튼·정오답 질문을 요구하는 방식은 피한다.

### 문맥에 따라 다음 표현을 사용한다

| 현재 | 개선안 | 적용 범위 |
|---|---|---|
| 우리 반 연습 자료 하나 만들기 | AI와 함께 수업·생활·업무 자료 만들기 | 여러 결과 유형을 허용하는 공통 실습 안내 |
| 실습: 우리 반 연습 자료 하나 | 실습: 학생용 생활 연습 화면 만들기 | 현재 v22의 웹 전용 기본 실습을 유지할 때 |
| 우리 반 연습 자료 | 카페 주문 연습 화면 / 안전교육 포스터 / 수업 타이머 | 개별 결과물·과제 |
| 우리 반의 불편 | 직접 해결해 보고 싶은 문제 | 주제 선택의 열린 항목 |
| 사용 조건에 표시하기 | 누가, 어디서, 어떻게 사용할지 정하기 | 활동지 제목. 항목은 기기·인터넷·설치·저장 등 구체적으로 유지 |
| 문제와 조건 | 해결할 문제와 사용 환경 | 제작 실습 순서 |
| 우리 학생을 위한 화면 원칙 | 학생의 수행 특성을 고려한 화면 설계 | 학생용 화면 설계 구역 |
| 우리 학생이 혼자 끝까지 할 수 있는가 | 목표 행동을 수행할 수 있는가? 필요한 도움은 무엇인가? | 사용자 확인 기준. 독립 수행이 목표인 사례에서는 기존 기준을 구체적으로 유지 |

첫 두 개선안은 적용 범위가 다르다. 공통 제목 아래 여러 형식을 허용할지, 기본 웹 실습을 유지할지 먼저 정하고 선택해야 한다.

### 공통 활동지는 자유 메모와 참고 질문을 함께 둔다

넓은 메모 공간을 두고, 생각이 막힐 때 참고할 질문을 옆이나 아래에 제시한다. 아래 다섯 질문은 작성 항목을 늘리는 제안이 아니며, 각각 별도 칸을 만들거나 모두 답하게 하지 않는다.

1. 누구의 어떤 문제를 해결하려는가?
2. 사용한 뒤 무엇이 가능해지거나 어떤 일이 쉬워져야 하는가?
3. 어떤 결과를 만들 것인가? — 웹 화면, 포스터, 안내문, 교사 도구 등.
4. 어디서 어떻게 사용할 것인가? — 기기 또는 지면, 설치·인터넷, 필요한 도움.
5. 이번에 어디까지 만들고, 무엇을 직접 확인할 것인가?

처음에는 떠오르는 문제와 해 보고 싶은 것부터 메모한다. 짧은 글·글머리표·그림을 허용하고, 모르는 것은 미정으로 남긴다. 개인정보와 사용 권한은 공통 고정 안내로 둔다. 이미 적은 대상을 다른 칸에 다시 적게 하지 않는다. 메모를 AI에게 주어 개요 문서를 정리하게 하고, 필요한 내용을 만들면서 보완한다.

결과별 설계 정보는 해당 결과를 만들 때 참고한다. 처음부터 모든 유형의 조건을 작성하게 하거나 아래 표를 추가 필수 양식으로 만들지 않는다.

| 결과 유형 | 별도로 정할 것 | 직접 확인할 것 |
|---|---|---|
| 학생용 웹 화면 | 행동 순서, 선택과 확인, 필요한 도움, 선택 변경·오류 복구 | 실제 기기에서 선택·이전·초기화·완료가 작동하는가 |
| 포스터·인포그래픽 | 전달할 행동, 지면 크기, 읽는 순서, 그림과 문구 | 한글·내용 근거·출력 크기·가독성이 적절한가 |
| 교사용 도구·문서 | 처리할 일, 입력과 출력, 기록 여부, 고쳐 쓸 부분 | 원하는 결과가 나오고 교사가 수정·재사용할 수 있는가 |

‘3~5단계’, ‘한 화면 한 행동’, ‘틀리면 정답 강조’는 공통 계획의 필수 규칙으로 사용하지 않는다. 웹 사례에서 교육 목표와 실제 기능에 맞춰 적용한다. 학생의 선호 선택은 오답으로 처리하지 않는다.

## 개선 순서와 영향 범위

1. **공통 이름과 범위 결정:** 개요·최신 흐름에 연수 전체, 기본 웹 실습, 선택 과제의 관계를 한 문단으로 명시한다.
2. **교재 문구 정리:** 2부 2·9·25·28·30쪽, 활동지 제목·항목, `practice/README.md`를 문맥별로 정리한다. 단순 검색·일괄 치환은 하지 않는다.
3. **활동지 구조 정리:** 대상·목표 반복을 줄이고, 자유 메모 공간과 선택적으로 참고할 질문을 둔다. 결과 유형별 기준은 필요할 때 안내하며 필수 작성칸을 늘리지 않는다. 기존 A4 앞뒤를 유지할지는 정보량과 실제 작성 공간으로 판단한다.
4. **대본과 과제 연결:** 대본의 발화는 자연스러움을 유지하면서 제목·활동지 번호·요청문을 맞춘다. 기존 Padlet 과제의 개요·설계 문서를 다시 쓰게 하지 않는다.
5. **출력과 운영 확인:** HTML→PDF로 다시 만들고 수정 페이지를 확인한다. 결과 유형을 확대하면 전체 흐름과 최종 출력물도 함께 검토한다.

표현만 정리하면서 기본 웹 실습을 유지하면 중간 영향도다. 기본 실습 자체를 웹·포스터·교사 도구 선택형으로 바꾸면 높은 영향도다. 후자는 완료 기준과 활동지·요청문·대본을 함께 바꿔야 한다.

## 지침에 반영할 때의 제안

반복되는 문제이므로 실제 수정 단계에서 `CONTENT_STYLE_GUIDE.md`에 짧은 원칙을 넣는 것이 적절하다.

> 공통 안내와 특정 사례의 범위를 구분한다. ‘우리 반’, ‘자료’, ‘조건’처럼 범위가 넓은 말은 문맥에 맞게 대상·결과물·사용 환경을 명시한다. 교재의 제목과 활동 항목은 참가자가 할 일을 드러내고, 같은 정보를 여러 칸에서 다시 작성하게 하지 않는다.

표현 구분은 기존의 표준 용어·사용자 안내 기준을 보완하는 제안이다. 후속 요청으로 작성 양식의 유연성은 `CONTENT_STYLE_GUIDE.md` 3절과 `docs/GUIDELINE_CHANGELOG.md`에 반영하고, [참가자 활동 안내](../practice/activity_guide.md)를 추가했다. 대본과 개요의 1부 7·2부 31쪽, 강의 흐름의 운영 메모도 이에 맞췄다. PDF·인쇄용 활동지의 문구·레이아웃 변경은 아직 적용하지 않았다.

## 결론

쉬운 표현을 유지하면서 **공통 제목은 넓고 정확하게, 제작 사례는 구체적으로, 활동 질문은 실제 행동 중심으로** 정리하는 것이 좋다. 특수교육 사례와 학생 이해의 가치는 유지하고, 연수 실습·학생 연습·교사 업무를 문맥에 따라 분명히 구분한다.
