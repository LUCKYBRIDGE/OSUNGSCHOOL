# OSUNGSCHOOL 강의자료 v2 수정 계획

## 1. 현재 PDF의 UI·UX 진단

현재 자료는 한글 깨짐이나 치명적 겹침은 크게 보이지 않지만, 강의 대상이 초보 교사라는 점에서는 다음 문제가 있다.

### 1) 화면이 너무 '개발자 문서 요약'처럼 보인다

- AGENTS.md, Docs, Skills, Agents, Hooks, Commands, Memory, MCP가 각각 설명되지만, 초보자 입장에서는 낱말이 계속 늘어나는 느낌이 강하다.
- 각 요소의 역할은 설명되지만, 실제로 한 작업 안에서 어떤 순서로 쓰이는지 체감하기 어렵다.
- 해결 방향은 용어를 먼저 외우게 하지 않고, '영화표 구매 연습 웹자료를 만든다'는 하나의 예시 안에서 각 요소가 왜 필요한지 보여주는 것이다.

### 2) 일부 슬라이드는 미관상 비어 보이거나 반복감이 있다

- 중앙 원형 아이콘 하나와 짧은 목록만 있는 슬라이드가 반복되어 자료의 밀도 차이가 크다.
- 반대로 23번 슬라이드처럼 설명과 도식이 동시에 많아지면 시선이 분산된다.
- 해결 방향은 '개념 설명 슬라이드'와 '예시 적용 슬라이드'를 번갈아 배치하는 것이다.

### 3) 초보자용 친절한 비유가 더 필요하다

- Harness, Loop, Graph는 좋은 개념이지만, 현재는 여전히 개발자 용어 중심이다.
- 교사 연수에서는 '학교 운영 체계', '업무 분장', '업무 매뉴얼', '결재·인계', '수업자료 제작 체크리스트'로 설명하는 편이 낫다.
- 용어는 남기되, 먼저 생활 언어로 이해시킨 뒤 영어 용어를 붙여야 한다.

### 4) 목차 구조는 있으나 장면 전환이 약하다

- INTRO, HARNESS, COMPONENTS, PROJECT, UX, DESIGN TOOLS, DEVELOP, PRACTICE, CLOSING으로 구분되어 있으나, 실제 PDF에서는 장 구분이 강하게 보이지 않는다.
- 각 장 시작에 '지금부터 무엇을 배울지'를 안내하는 구분 슬라이드가 필요하다.
- 초보자 대상 강의에서는 길 안내가 곧 UX이다.

### 5) 디자인 도구 설명은 좋은데 작업 연결성이 더 필요하다

- DESIGN.md, 이미지 도안, Claude Design, Stitch, Figma, MCP가 모두 들어가 있으나, '어떤 상황에서 무엇을 쓰는가'가 더 선명해야 한다.
- 해결 방향은 도구를 나열하지 않고, 다음 네 흐름으로 제시하는 것이다.
  - ChatGPT/Gemini: 가장 빠른 도안 탐색
  - Claude Design: 대화형 캔버스로 시안과 프로토타입 만들기
  - Figma: 정밀한 화면 조정과 협업
  - Stitch + Antigravity: Google 생태계 안에서 디자인에서 구현으로 넘기기

## 2. v2 강의 흐름 제안

### 0부. 시작: 오늘 강의의 목표

- 이 강의는 전문 개발자 양성이 아니라 교사가 필요한 도구를 AI와 함께 만드는 방법을 익히는 강의이다.
- 목표는 '코드를 많이 쓰기'가 아니라 '문제 정의, 사용자 흐름, 화면 기준, 검증 기준을 AI에게 전달하기'이다.

### 1부. 바이브코딩을 교사 언어로 다시 이해하기

핵심 문장:

> 바이브코딩은 개발자가 되는 수업이 아니라, 내가 아는 학생과 수업 상황을 AI가 만들 수 있는 형태로 번역하는 과정이다.

예시:

- 나쁜 요청: 카페 키오스크 만들어줘.
- 좋은 요청: 특수학교 고등과정 학생이 음료 2개 중 하나를 고르고, 크기를 선택한 뒤, 결제 버튼을 누르는 3단계 연습 웹자료를 만들어줘. 한 화면에는 하나의 행동만 보여줘.

### 2부. 해커톤 우승자의 하네스에서 구조만 가져오기

ECC는 Anthropic x Forum Ventures 해커톤 우승자가 공개한 Claude Code 하네스 사례로 소개한다. 중요한 메시지는 '이걸 그대로 설치하자'가 아니라 '우승자는 프롬프트 하나가 아니라 반복 가능한 작업 환경을 만들었다'이다.

초보자용 설명 순서:

1. 우승자가 쓴 것은 거대한 마법 프롬프트가 아니다.
2. 프로젝트 규칙, 작업 매뉴얼, 담당 역할, 자동 점검, 도구 연결, 상태 저장을 묶은 체계이다.
3. 교사도 작은 버전으로 따라 할 수 있다.
4. OSUNGSCHOOL 저장소가 바로 작은 하네스 예시이다.

### 3부. 하네스 구성요소를 하나의 예시로 묶기

예시 과제: 영화표 구매 연습 웹자료

| 구성요소 | 초보자용 비유 | 실제 역할 | 영화표 예시 |
|---|---|---|---|
| AGENTS.md | 학교 공통 규칙 | 항상 지킬 원칙 | 큰 버튼, 한 화면 한 행동, 학생 개인정보 금지 |
| Docs | 업무 자료철 | 대상·문제·설계 배경 | 영화표 구매 단계와 학생 수준 설명 |
| Skills | 업무 매뉴얼 | 특정 작업 순서 | UI 검토 절차, PDF 제작 절차 |
| Agents | 담당자 | 역할 분담 | 기획 담당, 화면 담당, 구현 담당, 검토 담당 |
| Commands | 단축 호출 | 반복 작업 실행 | /plan, /review, /verify |
| Hooks | 자동 점검 | 사건 발생 시 자동 실행 | 저장 전 형식 검사, 배포 전 빌드 검사 |
| Memory/Handoff | 인계장 | 현재 상태와 다음 작업 | 완료한 기능, 남은 문제, 다음 세션 할 일 |
| MCP/Tools | 장비 지급 | 외부 도구 연결 | GitHub, Figma, 브라우저, 파일 시스템 |

### 4부. 초보자를 위한 UI·UX

강의 핵심은 '예쁜 화면'이 아니라 '학생이 헤매지 않는 화면'이다.

추가할 예시:

- 나쁜 화면: 한 화면에 메뉴 12개, 작은 버튼, 광고, 여러 결제수단, 뒤로가기 없음.
- 좋은 화면: 선택지 2개, 큰 그림, 한 단계 한 행동, 현재 단계 표시, 다시 하기 버튼.

슬라이드에는 실제 미니 와이어프레임을 넣는 것이 좋다.

### 5부. DESIGN.md와 이미지 도안

DESIGN.md는 디자이너용 전문 문서가 아니라, AI에게 '매번 같은 화면 기준을 지키게 하는 약속 문서'로 설명한다.

초보자용 문장:

> DESIGN.md는 AI에게 '우리 반 자료는 항상 이런 크기, 이런 글씨, 이런 버튼으로 만들어야 한다'고 알려주는 화면 제작 규칙이다.

이미지 도안 설명:

> 코딩하기 전에 그림으로 먼저 실패하면, 코드로 실패하는 시간을 줄일 수 있다.

### 6부. 디자인 도구 연결

도구 설명은 다음처럼 난이도별로 정리한다.

| 상황 | 추천 도구 | 설명 |
|---|---|---|
| 빠르게 화면 느낌 보기 | ChatGPT / Gemini | DESIGN.md를 붙이고 이미지 도안을 여러 장 만든다 |
| 대화하며 디자인 수정 | Claude Design | 디자인 캔버스에서 시안·프로토타입을 만든다 |
| Google 생태계에서 디자인→개발 | Stitch → Antigravity | Stitch에서 디자인하고 Antigravity로 넘긴다 |
| 정밀한 협업 설계 | Figma | 컴포넌트, 오토레이아웃, 프로토타입을 관리한다 |
| Figma를 개발 Agent에 연결 | Figma MCP | Claude Code, ChatGPT, Codex 등이 디자인 맥락을 읽게 한다 |

### 7부. 실습: 작은 자료를 끝까지 만들기

실습 주제는 전문 앱보다 작은 생활 연습 자료가 좋다.

- 카페 주문 연습
- 영화표 구매 연습
- 병원 접수 연습
- 버스 타기 연습
- 감정 표현 선택 연습
- 급식 순서 확인 자료

실습 산출물은 다음 5개로 단순화한다.

1. PROJECT_OVERVIEW.md
2. DESIGN.md
3. 첫 화면 도안 1장
4. 구현된 웹자료
5. HANDOFF.md

## 3. 추가해야 할 슬라이드

### A. 목차 슬라이드

제목: 오늘의 길

1. 교사를 위한 바이브코딩 이해
2. 해커톤 우승자의 하네스에서 배울 점
3. AGENTS.md·Docs·Skills가 함께 일하는 방식
4. 학생이 헤매지 않는 UX 설계
5. DESIGN.md와 이미지 도안
6. Claude Design·Stitch·Figma 연결
7. 오성학교 실습 프로젝트

### B. ECC 사례를 더 쉽게 설명하는 슬라이드

제목: 우승자는 '프롬프트'보다 '작업환경'을 만들었다

- Anthropic x Forum Ventures 해커톤 우승 사례
- Zenith Chat을 Claude Code로 빠르게 구현
- 이후 작업 규칙·스킬·훅·에이전트·MCP를 공개
- 우리가 가져올 것은 규모가 아니라 구조이다

### C. 하네스 연결 예시 슬라이드

제목: 영화표 구매 연습 자료를 만든다면?

- AGENTS.md: 학생용 자료 원칙 고정
- Docs: 학생 수준과 활동 목표 기록
- Skill: UI 검토 절차 사용
- Agent: 화면 설계 담당과 구현 담당 분리
- MCP: Figma와 GitHub 연결
- Hook: 저장 전 형식 검사
- Memory: 다음 세션 인계

### D. 디자인 도구 선택 슬라이드

제목: 디자인 도구는 목적에 따라 고른다

- ChatGPT/Gemini: 가장 빠른 시안
- Claude Design: 대화형 디자인 캔버스
- Stitch: Google 생태계 UI 설계와 Antigravity 연결
- Figma: 정밀한 설계와 MCP 연결

### E. 초보자용 프롬프트 예시 슬라이드

제목: 나쁜 요청과 좋은 요청

나쁜 요청:

> 카페 키오스크 웹사이트 만들어줘.

좋은 요청:

> 특수학교 학생이 사용할 카페 주문 연습 웹자료를 만들어줘. 첫 버전은 음료 선택, 크기 선택, 주문 확인 3단계만 만든다. 한 화면에는 하나의 행동만 보이게 하고, 버튼은 크게 배치한다. 틀렸을 때는 다시 선택할 수 있게 한다.

## 4. 시각 디자인 수정 방향

- 장 구분 슬라이드를 6~7장 추가한다.
- 현재 원형 아이콘 중심 슬라이드는 일부만 유지하고, 예시 화면·흐름도·비교 화면을 늘린다.
- 23번 하네스 흐름 슬라이드는 2장으로 나눈다.
  - 1장: 구성요소 한눈에 보기
  - 2장: 영화표 구매 연습 예시로 실제 작동 보기
- 도구 설명 슬라이드는 각 도구 로고식 카드보다 '입력 → 도구 → 산출물 → 다음 단계' 흐름으로 바꾼다.
- 발표 화면에는 용어를 줄이고, 대본에는 상세 설명을 둔다.

## 5. 최종 방향

v2 자료는 '개발자에게 설명하는 AI 개발 워크플로우'가 아니라 '교사가 자신의 교육자료를 만들기 위해 이해해야 할 AI 작업환경'으로 재구성한다.

핵심 문장은 다음으로 정리한다.

> AI가 코드를 대신 쓰는 시대일수록, 교사의 역할은 줄어드는 것이 아니라 더 중요해진다. 학생을 아는 사람만이 좋은 문제, 좋은 흐름, 좋은 화면, 좋은 검증 기준을 줄 수 있기 때문이다.
