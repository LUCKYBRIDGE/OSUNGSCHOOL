# 강릉오성학교 AI·디지털 문제해결 실무 과정 개요 (v22)

## 대상

강릉오성학교 교사(전문 개발자가 아닌 특수교육 교사). 생활·수업·업무의 작은 불편을 AI와 디지털 도구로 직접 해결해 보는 실무형 연수다.

## 핵심 메시지

1. 만들 것은 앱이 아니라 해결할 문제다. 문제 한 문장과 사용 조건부터 정한다.
2. 좋은 질문 한 번보다 AI가 같은 기준으로 계속 일할 작업환경(규칙·문서·스킬·인계 파일)이 중요하다.
3. 교사의 도메인 지식(학생 이해)은 구현 능력만큼 중요한 입력이다.
4. 그럴싸한 화면보다 학생이 헤매지 않는 흐름이 먼저다.
5. 작게 만들고, 완료 기준으로 직접 확인하고, 공개한 뒤 관찰해 다시 고친다.
6. AI는 교사가 쓰고, 학생은 완성된 화면만 쓴다. 개인정보는 넣지 않는다.

## 강의 큰 흐름

### 1부. 문제 정의와 AI 작업환경 (42쪽)

- 작은 불편에서 시작하기: 문제 한 문장, 사용 조건, 조건에 따른 제작 방식
- AI와 말이 통하는 최소 지식: 화면·처리·기록, API/MCP, GitHub/배포
- 질문 한 번에서 작업환경으로: 하네스, ECC 공개 사례, 해커톤 수상자와 현장 지식 파일
- 작업환경을 이루는 것들: 규칙 파일, 프로젝트 문서, 스킬, 규칙·스킬·훅 비교, 에이전트, 도구 연결, 완료 기준
- 작업공간과 인계: 프로젝트 폴더, 공통/프로젝트 규칙, HANDOFF.md, 요청문

### 2부. UX/UI 설계와 구현·검증 실습 (35쪽)

- 잘 쓰이는 화면: 그럴싸한 화면과 쓸 수 있는 화면, UX/UI, 사용자 흐름
- 특수교육 화면 원칙: 한 화면 한 행동, 학생별 조절, 틀렸을 때의 화면
- DESIGN.md: 화면 기준을 파일로
- 그림으로 먼저 확인하기: 그림 시안, 시안 도구 표, knollab-001 비교 실험
- 만들고 확인하고 공개하기: 한 화면씩 요청, 검토와 검증(교사 5분 확인), GitHub Pages
- 실습: 설치 없이 브라우저에서, 학교에서 지킬 것, 3~5단계 생활 연습 자료 하나 완성

### 실습 자료

- 인쇄용 안내문(A4 앞뒤)과 복사용 요청문·양식: `practice/`
- 추가 과제 운영: [과제 안내](../practice/assignments/README.md). 과제 1의 아이디어 정리 뒤 과제 2(키오스크)·3(안전교육 포스터/인포그래픽)·4(자유 결과물) 중 하나를 선택한다.
- 공통 제출 문서는 overview.md 또는 prd.md 하나와 design.md다. Figma MCP는 연결 가능한 경우 선택 심화로 활용한다. 파일·사이트·저장소·Figma 링크를 결과물의 성격에 맞게 제출하고 실제 확인한 결과를 기록한다.
