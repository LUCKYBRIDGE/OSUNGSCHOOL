## 1부 묶음

1. 작은 불편에서 시작한다 (3~9쪽): 예약 종료 사례, 학교의 불편, 좋은 문제의 조건, 한 문장 틀, 사용 조건, 조건에 따라 달라지는 제작 방식(웹앱·설치형)
2. AI와 말이 통하는 최소 지식 (10~15쪽): 화면·처리·기록, API와 MCP, GitHub와 배포, AI의 질문에 답하기, 비교 요청
3. 질문 한 번에서 작업환경으로 (16~22쪽): 긴 작업의 문제, 하네스, '더 잘해' 대신 빠진 것 채우기, ECC, 해커톤 수상자와 현장 지식 파일
4. 작업환경을 이루는 것들 (23~33쪽): 학교 비유 지도, 규칙 파일·도구별 파일·프로젝트 문서·스킬, 규칙·스킬·훅 비교, 에이전트·도구 연결·완료 기준, 최소 구성
5. 작업공간과 인계 (34~42쪽): 프로젝트 폴더, 공통·프로젝트 규칙, 인계 파일, 이 저장소 사례, 요청문 두 가지, 정리, 참고 자료

## 2부 묶음

1. 잘 쓰이는 화면이란 (3~8쪽): 그럴싸한 화면과 쓸 수 있는 화면, 목업 비교, UX/UI, 사용자 흐름
2. 우리 학생을 위한 화면 원칙 (9~12쪽): 여섯 원칙, 학생별 조절, 틀렸을 때의 화면
3. DESIGN.md (13~15쪽): 개념과 예시, 요청문
4. 그림으로 먼저 확인하기 (16~20쪽): 시안 과정, 도구 선택 표, 그림 시안 요청, knollab-001 사례
5. 만들고, 확인하고, 공개하기 (21~24쪽): 한 화면씩 요청하고 확인, 검토와 검증(교사 5분 확인), 공개하고 관찰하기
6. 실습 (25~35쪽): 실습 도구, 학교에서 지킬 것, 주제, 목표, 순서, 여섯 질문, 막혔을 때, 기억할 문장, 참고 자료, 질문과 나눔

## 운영 메모

- 인쇄용 안내문(`practice/`)은 앞면을 강의 중에 채우고, 뒷면 요청문은 실습에서 쓴다.
- 활동지의 질문과 칸은 참고로 쓴다. 자유 메모로 시작하고 미정은 제작 중 보완한다. 운영 안내는 [자유 메모로 시작하는 활동 안내](../practice/activity_guide.md)를 따른다.
- 1부 39·40쪽 요청문은 안내문 뒷면 요청 1·5와 같다. 2부 실습에서 다시 쓴다.
- 2부 실습 시간은 예시(총 60분)다. 시간이 모자라면 시안 단계를 건너뛰고 공유를 지킨다.
