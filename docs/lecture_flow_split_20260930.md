## 1부 묶음

1. 작은 불편에서 시작한다 (3~9쪽): 예약 종료 사례, 학교의 불편, 좋은 문제의 조건, 한 문장 틀, 사용 조건
2. AI와 말이 통하는 최소 지식 (10~16쪽): 웹앱/설치형, 화면·처리·기록, API/MCP, GitHub/배포, AI의 질문에 답하기
3. 질문 한 번에서 작업환경으로 (17~24쪽): 긴 작업의 문제, 하네스, '더 잘해' 대신 빠진 것 채우기, ECC, 해커톤 수상자
4. 작업환경을 이루는 것들 (25~34쪽): 학교 비유 지도, 규칙·도구별 파일·문서·스킬·에이전트·도구 연결·완료 기준, 최소 구성
5. 작업공간과 인계 (35~44쪽): 프로젝트 폴더, 공통/프로젝트 규칙, 인계 파일, 이 저장소 사례, 요청문 두 가지, 정리

## 2부 묶음

1. 잘 쓰이는 화면이란 (3~9쪽): 그럴싸한 화면과 쓸 수 있는 화면, 목업 비교, UX/UI, 사용자 흐름
2. 우리 학생을 위한 화면 원칙 (10~13쪽): 여섯 원칙, 학생별 조절, 틀렸을 때의 화면
3. DESIGN.md (14~17쪽): 개념, 예시, 요청문
4. 그림으로 먼저 확인하기 (18~24쪽): 시안 과정, 도구 선택 표, 그림 시안 요청, Stitch·Claude Design, Figma, 공통 흐름
5. 만들고, 확인하고, 공개하기 (25~31쪽): 작게 나누기, 구현 요청문, 검토와 검증, 5분 확인, 배포, 배포 후 관찰
6. 실습 (32~41쪽): 주제, 목표, 순서, 여섯 질문, 막혔을 때, 결과 폴더, 기억할 문장
