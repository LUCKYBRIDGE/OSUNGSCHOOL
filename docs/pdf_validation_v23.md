## 검증

- Windows Chrome + Playwright(`build.cjs`): 기존 `qa.js`·`handout-qa.js`로 인쇄 렌더링을 검사했다. 1부 `QA slides=42 / OK`, 2부 `QA slides=35 / OK`, 활동지 `QA pages=2 / OK`.
- 기존 자동 검사 기준(일반 텍스트 20px, 활동지 본문 9pt·바닥글 8pt)의 미달 0건. 쪽·상자 넘침, 본문 밖 글자, 안전영역 이탈, 의도하지 않은 상자 겹침 0건.
- pypdf로 모든 쪽이 열리고 텍스트가 존재하는지, 슬라이드 전 쪽이 16:9인지, 한글 대체 문자 `�`가 없는지 확인했다.
- 사용된 PDF 글꼴 리소스는 모두 포함되어 있다: 1부 6종, 2부 6종, 활동지 5종, 대본 5종(부분 포함 글꼴 이름 기준).
- pypdfium2로 PDF 전체 100쪽을 렌더링하고 모든 쪽을 검수 이미지로 확인했다. 활동지 앞뒤는 흑백, 수정된 주요 슬라이드·활동지는 개별 확대 화면으로 확인했다. 대본의 제목·본문·쪽 번호·전환 페이지와 줄바꿈을 확인했다.
- ZIP 내부 파일과 저장소 최종 파일이 바이트 단위로 같은지 확인하고 CRC 검사(`testzip`)를 통과했다. ZIP의 `읽어주세요.txt`에 파일별 SHA-256을 제공한다.

## 내용 일치

- 대본 1부 01~42·2부 01~35에 누락·중복 없음, 예상 질문 Q1~Q16 유지. 개요와 실제 슬라이드의 해당 제목·목적을 함께 수정했다.
- 공통 활동명은 수업·생활·업무 자료 만들기. 카페 사례와 학생용 화면 원칙은 교육적 판단 예시로 유지했다.
- 활동지의 고정 답칸·3~5단계 흐름도·전 항목 작성 요구를 참고 질문 세 개와 자유 메모·결과 메모로 바꿨다. 관련 대본의 활동지 번호도 앞면 2·4번으로 맞췄다.
- 자유 선택에는 오답이 없으며, 정답이 있는 학습 과제에서만 힌트·정답 강조를 쓴다.
- 요청 1은 1부 39쪽·활동지·복사용 안내에 같은 의미로 반영했다. 웹 화면 요청은 예시이며 다른 결과물은 주제와 사용자에 맞게 조정한다.
- 저장 파일명은 `index.html`, 배포 예시는 저장소 맨 위 + Pages `main · /(root)`. 배포 후 실제 주소를 확인한다.
- 새 대화 검토에는 DESIGN.md와 최신 HTML을 함께 전달한다. 컨텍스트의 절대적 표현도 완화했다.
- Gem 개인 계정의 나이 안내에 한국 14세와 학교 계정의 별도 조건을 반영했다. 출처 [20]의 Google 공식 나이 안내, [16]의 GitHub 진입 파일 안내를 2026-09-30에 재조회했다.
